Hi,

Ways to reproduce the issue:
git checkout 47b81d4c
make config-musl
make

Compilation fails with messages:
```
...
../../../bin/scc -t linux -a amd64 -O1 -o ctype.6l -c ctype.c
ctype.c:6: error: '_C' undeclared
ctype.c:7: error: '_S' undeclared
ctype.c:10: error: '_SP' undeclared
ctype.c:10: error: '_P' undeclared
ctype.c:12: error: '_D' undeclared
ctype.c:14: error: '_U' undeclared
ctype.c:14: error: '_X' undeclared
ctype.c:18: error: '_L' undeclared
ctype.c:22: error: initializer element is not constant
make: error: target ctype.6l: error 256
make: error: target ctype: error 256
make: error: target src/libc: error 256
make: error: target amd64: error 256
make: error: target all: error 256
make: *** [Makefile:15: all] Error 1
```

It seems to me `make config-musl` refers to using musl as the
standard C library. The ctype.c file mentioned in the message
is the scc internal libc. In commit 1e0f1124, src/libc/rules.mk
CPPINCLUDES was removed so the required header
file(include/scc/ctype.h) is not included while compiling scc
internal libc with LIBPROFILE=musl. I can see the compilation
works when LIBPROFILE=scc, because 'include/scc/bits/scc/sys-scc.h'
adds path "%p/include/scc/". The optimal method may be skip
compiling src/libc when LIBPROFILE=musl.

Best,
Zhaoming
