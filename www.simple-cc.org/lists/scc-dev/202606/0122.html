Hi,

With commit 027ea37e and amd64 machine, when compile and run the
following program:
```
struct S {
        int a[2];
        int b;
};

int main(void) {
        struct S s = { {1, 2}, 1};
        int a[3] = {1,2,3};

        return a[s.b++];
}
```
It gives:
```
$ ./a.out
Bus error
```

After digging into the qbe and assembly code, I found the wrong
type is loaded:

```
        %.L15 =l loadl %.L14
```

L14 points to the address of `s.b`, and the type of `s.b` is `int`.
In QBE, type 'l' refers to 64-bit integers, but `s.b` is a 32-bit
type integer, so an undefined value is loaded to L15.

QBE code:
```
type :.3 = align 4 { 12 }
data $.L7 = align 4 {
        w 1,
        w 2,
        w 0,
}
data $.L10 = align 4 {
        w 1,
        w 2,
        w 3,
}
export function w $main()
{
_at_main.body
_at_.L21
        %s.L9 =l alloc4 12
        %a.L11 =l alloc4 12
                blit $.L7,%s.L9,12
                blit $.L10,%a.L11,12
        %.L14 =l add %s.L9,8
        %.L15 =l loadl %.L14
        %.L16 =w add %.L15,1
                storew %.L16,%.L14
        %.L18 =l shl %.L15,2
        %.L19 =l add %a.L11,%.L18
        %.L20 =w loadsw %.L19
                ret %.L20
_at_.L22
                ret 0
}
```

I found the issue is in src/cmd/scc-cc/cc2/qbe/cgen.c line 485:
```
        ret = load(&l->type, l);
```
Before line 484 `lhs_rhs(&l, &r);`, variable `l` is:
```
{op = 46 '.', type = {size = 4, align = 4, id = 0, flags = 3}...
```
However, because `l` is `struct field access`, the value of `l`
changes after lhs_rhs():
```
{op = 78 'N', type = {size = 8, align = 8, id = 0, flags = 2}...
```
Value `l->type` is still used to load data from l, so the wrong
type is used.

The optimal method I come up with is storing `l->type` before
lhs_rhs() and pass it to load(), but I'm not sure if it's indeed
the best, so I report this finding here.

Best,
Zhaoming
