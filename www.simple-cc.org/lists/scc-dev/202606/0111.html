On Fri, May 29, 2026 at 01:20:05AM +0000, Zhaoming Luo wrote:
> It seems to me `make config-musl` refers to using musl as the
> standard C library. The ctype.c file mentioned in the message
> is the scc internal libc. In commit 1e0f1124, src/libc/rules.mk
> CPPINCLUDES was removed so the required header
> file(include/scc/ctype.h) is not included while compiling scc
> internal libc with LIBPROFILE=musl. I can see the compilation
> works when LIBPROFILE=scc, because 'include/scc/bits/scc/sys-scc.h'
> adds path "%p/include/scc/". The optimal method may be skip
> compiling src/libc when LIBPROFILE=musl.

Good catch. It seems that I had the libc already compiled when
I tested that patch. I tried your approach to skip the libc build
for LIBPROFILE=musl but that generates other problem because
the proto files used in the install target require the different
libcs. I pushed a change taking back CPPINCLUDES even when it is
not needed in the configs that use the scc libc, but it is required
for the musl configurations. I while try think a bit more about
this topic and see if I can get a better solution.
