On Mon, Jun 22, 2026 at 06:59:22AM +0000, Zhaoming Luo wrote:
> After digging into the qbe and assembly code, I found the wrong
> type is loaded:
>
> ```
> %.L15 =l loadl %.L14
> ```
>
> L14 points to the address of `s.b`, and the type of `s.b` is `int`.
> In QBE, type 'l' refers to 64-bit integers, but `s.b` is a 32-bit
> type integer, so an undefined value is loaded to L15.

Yes, but the main problem here is that we are doing a unaligned access
because we use an address to a 32 bit value to get a 64 bits, this is
why we get the bus error.

> I found the issue is in src/cmd/scc-cc/cc2/qbe/cgen.c line 485:
> ```
> ret = load(&l->type, l);
> ```
> Before line 484 `lhs_rhs(&l, &r);`, variable `l` is:
> ```
> {op = 46 '.', type = {size = 4, align = 4, id = 0, flags = 3}...
> ```
> However, because `l` is `struct field access`, the value of `l`
> changes after lhs_rhs():

Yeah, after the call to lhs_rhs() which calls lhs() l is a pointer
to the adress that we have to load, and obviously that is going
to be a 64 bit value. I think we have the same problem with arrays
too.

> The optimal method I come up with is storing `l->type` before
> lhs_rhs() and pass it to load(), but I'm not sure if it's indeed
> the best, so I report this finding here.

I think we have to understand a bit better the issue, because we
have 3 calls to lhs_rhs() and I think all of them have the same
problem (from current master):

        484 lhs_rhs(&l, &r);
        496 lhs_rhs(&l, &r);
        519 lhs_rhs(&l, &r);

After reviewing every one of them I think the best solution is
to change:

        lhs_rhs(&l, &r);
        ret = load(&l->type, l);

to

        lhs_rhs(&l, &r);
        ret = load(&r->type, l);

because the type of both operands must be the same (otherwise they
cannot be operands of the same expression). This trick is used in
other place:

        495 if (r->type.size < 4) {
        496 lhs_rhs(&l, &r);
        497 aux.op = np->u.subop;
        498 aux.left = load(&r->type, l);

I didn't test it, but I think it should work. Do you want to try the
patch and the tests for struct (the one you already got) and for array?
